# Wave 1: read-only CRM skills on the CSV route

Review: freeroll — read-only against a synthetic CSV export; skills write only proposal, audit, and calibration files inside brain/; no sends, no live system touched. The live connection path is a separate plan that goes through /codex-plan-review.

Julian (2026-09-27): skills connect to CRMs directly, with a CSV export as the fallback. Build the CSV route first while the sandbox CRM is set up.

## Requirements

- **R1** A shared CRM export format (`brain/crm-export/`) with companies and contacts, vendor-neutral, documented in one README.
- **R2** A synthetic example export with planted defects: a duplicate company, an impossible revenue value, a detected value that disagrees with a confirmed value, a confirmed value with no date, an invalid email, a contact who left.
- **R3** A shared proposal format (`brain/proposals/`) that lists each change as object, record ID, field, old value, new value, reason, and evidence, with a status a person sets. No skill applies a proposal in wave 1.
- **R4** A shared field-rules file (`brain/field-rules.md`) naming each detected / confirmed field pair and the precedence rule.
- **R5** `icp-filter-calibration`: turns `brain/icp.md` into a machine filter in `brain/filters.md`, runs it on the export, and writes a calibration record: match count against the team's target range, and every criterion whose written definition leaves a record ambiguous.
- **R6** `data-accuracy-audit`: samples accounts and contacts from the export, checks each sampled field it can check from the data, marks the rest for a human check, scores the checked fields against the team's bar, and traces each error to its source. Proposes fixes to the source, not to single records.
- **R7** `crm-field-provenance`: reviews the export and any proposal file against `brain/field-rules.md`; flags any change that would overwrite a confirmed value, any confirmed value with no date, and any detected value that disagrees with a confirmed value.
- **R8** Every skill has a "Connect" section: use a live CRM connection when one is available (read-only in wave 1), otherwise ask for an export in the R1 format.
- **R9** Each skill follows the brain rules: evidence on every claim, gaps stay gaps, a person approves every change, and nothing is sent or written to a CRM.

## Tasks

## Behavior and failure cases

- Pass: each skill finds the planted defects that fall in its scope, cites the row and field, and writes only its own output file.
- Fail: a planted defect in scope is missed; a skill states a value no file holds; a skill writes outside its output folder or edits the export.
